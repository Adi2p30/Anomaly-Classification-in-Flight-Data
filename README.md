# Anomaly Classification in Flight Data — Initial Run

A synthetic-data pipeline and physics-feature classifier for detecting an
injected "wrong frequency" anomaly window inside an otherwise-clean
sine-wave signal (a stand-in for a sensor channel that should oscillate at
one steady frequency, e.g. a flight-instrument reading).

The pipeline:

1. generates clean sine-wave signals at several frequencies/phases,
2. injects a smooth, mean-preserving anomaly (a different frequency, active
   for a random 10–30s window) into copies of those signals,
3. records the ground-truth anomaly window,
4. extracts physics/signal-processing features per sliding window and
   trains a classifier to relocate that window in unseen signals,
5. evaluates and plots the results, and
6. provides an interactive matplotlib tool to explore any generated signal.

## v3

A harder, more realistic variant of this pipeline lives in `v3/` — a wider
base-signal grid, reintroduced measurement noise and a non-stationary
(drifting, harmonic-bearing) baseline, three anomaly types (frequency
swap, amplitude dropout, DC offset jump) instead of one, seven additional
physics/vibration-inspired features, and a Random Forest vs.
HistGradientBoosting vs. classical-baseline comparison with cross-validated
confidence intervals. `Initial_Run/` is unmodified and remains the
original, deliberately-legible reference pipeline. See
[`v3/identifying_anomalies/MODEL_ARCHITECTURE_V3.md`](v3/identifying_anomalies/MODEL_ARCHITECTURE_V3.md)
for what changed and why, and the results.

## Running the pipeline

Run in order from `Initial_Run/`:

```bash
python generating_data/scripts/generate_clean_signals.py
python generating_data/scripts/inject_anomaly.py
python identifying_anomalies/scripts/build_dataset.py
python identifying_anomalies/scripts/train_model.py
python identifying_anomalies/scripts/evaluate_and_reconstruct.py
python identifying_anomalies/scripts/make_plots.py
python identifying_anomalies/scripts/interactive_viewer.py [filename]   # optional (clean or anomaly/control filename); with no arg, and a model evaluated, prompts you to pick a held-out test file. Needs a display.
```

Each step reads the previous step's output and writes into its own data
folder; all parameters (sampling rate, frequency/phase grid, anomaly
ranges, window size, model hyperparameters) live in one place:
`generating_data/scripts/config.py`.

## Data generation

Each signal is a pure `A * sin(2π f0 t + φ0)`, sampled at `fs = 1000 Hz` for
`120 s` (120,000 samples) — no measurement noise is added, so a clean file
and an anomaly file are byte-for-byte identical outside the injected
window (see below). The base grid is 5 frequencies × 3 phases = 15 clean
signals (`config.py: BASE_FREQS`, `BASE_PHASES`).

## Anomaly injection: no spikes, exact mean preservation

For a clean signal `s(t)` and a randomly chosen window `[i0, i0+N_a)`
(duration `Uniform(10, 30)s`, at a random start time), the injected
anomaly component is:

```
env(τ)   = tukey(N_a, alpha=0.15, sym=True)        # 0 at both edges, smooth
raw_a(τ) = A_a · sin(2π f_a τ + φ_a)                # a different frequency f_a
k        = sum(env · raw_a) / sum(env)
c(τ)     = env(τ) · raw_a(τ)  −  k · env(τ)
```

`c(τ)` is added into `s` only inside the window. Both terms in `c` carry
the `env(τ)` factor, so `c` and its derivative are exactly 0 at the window
boundaries — no discontinuity, no spike, a C¹-continuous splice — and
`sum(c)` over the window is exactly 0 by construction, so the **global mean
of the record is preserved to floating-point precision** with zero change
to any sample outside the window. `inject_anomaly.py` asserts this for
every file it writes (mean preserved to `<1e-8`, zero change outside the
window). The anomaly frequency is drawn as a multiple of the base
frequency (`f_a = f0 · U`, offset far enough to be distinguishable), and
its amplitude is drawn from `{0.5, 0.75, 1.0, 1.5, 2.0} × A`
(`config.py: AMP_RATIO_CHOICES`) — tuned so the anomaly is always plainly
visible by eye against the clean sine, not just detectable statistically.
This is a deliberate choice for a legible demo; see
[`identifying_anomalies/MODEL_ARCHITECTURE.md`](identifying_anomalies/MODEL_ARCHITECTURE.md#making-this-harder--more-realistic)
for how to push the amplitude back down (or otherwise make the task
harder) once you want to stress-test the model rather than look at it.

Each anomaly CSV carries a per-sample `is_anomaly` flag; the authoritative
ground truth lives in `anomaly_data/labels.csv` (one row per file: base
signal, injected frequency/phase/amplitude ratio, and the true
`start_idx`/`end_idx` window). A handful of anomaly-free "control" files
are also generated as true negatives.

## The model

**Primary model**: `sklearn.ensemble.RandomForestClassifier` (scikit-learn
1.9), trained in `train_model.py` and saved to `model/model.joblib`.
Exact hyperparameters (set in `config.py: RF_PARAMS`):

| param | value |
|---|---|
| `n_estimators` | 300 |
| `min_samples_leaf` | 3 |
| `class_weight` | `balanced` |
| `random_state` | 42 |
| (everything else) | scikit-learn defaults — `criterion="gini"`, `max_depth=None`, `max_features="sqrt"`, `bootstrap=True` |

It's trained on 8 physics/signal-processing features per 2-second sliding
window (not raw samples) — see the table below. A
`sklearn.model_selection.GroupShuffleSplit`, grouped by *base signal id*
(not by anomaly-file id), holds out 3 of 15 base frequency/phase
combinations entirely for testing, so the model is never evaluated on a
(frequency, phase) pair it saw during training.

**Comparison baseline**: a classical single-feature threshold detector —
`lsq_residual_energy` (see below) thresholded at the value that maximizes
Youden's J on the training split (`baseline_threshold.json`). This is the
textbook matched-filter / energy-detector answer to "is there another
tone in this window," reported alongside the Random Forest to show what
the extra 7 features and the forest actually buy you.

| feature | what it measures |
|---|---|
| `dominant_freq_offset` | FFT peak frequency vs. estimated f0 |
| `out_band_power_ratio` | fraction of spectral power outside a band around f0 |
| `inst_freq_std` / `inst_freq_dev` | Hilbert-transform instantaneous frequency spread / offset from f0 |
| `lsq_residual_energy` | residual energy after least-squares fitting a pure f0 sinusoid — a matched-filter / energy-detector statistic for narrowband intrusion |
| `zcr_deviation` | zero-crossing rate vs. the theoretical rate for f0 |
| `rms` | signal energy |
| `spectral_entropy` | how spread-out the spectrum is |

`f0` itself is estimated per file from a whole-record Welch periodogram —
never read from the generation parameters — so the pipeline stays honest
about what a real detector would have access to.

### Localizing the window precisely

A naive reconstruction — union of windows the classifier calls positive —
quantizes the predicted boundary to the window stride (200 samples /
0.2s). Instead, `reconstruct.py` assigns each window's predicted
*probability* to its center time, linearly interpolates that probability
curve to every sample, and takes the 0.5-crossing as the boundary. This is
shared by both `evaluate_and_reconstruct.py` and `interactive_viewer.py`.

## Results — how the model did, with evidence

From `model/metrics.json` and `model/eval_amp_sweep.csv`
(3 held-out base signals never seen in training, ~8,900 test windows):

| metric | Random Forest | classical baseline (`lsq_residual_energy` threshold) |
|---|---|---|
| Precision | 0.979 | 0.982 |
| Recall | 0.992 | 0.990 |
| F1 | **0.986** | 0.986 |
| ROC-AUC | **0.9998** | 0.9997 |

At these amplitude ratios (0.5–2.0× the base amplitude) the anomaly is
large enough that the single-feature classical baseline now performs
about as well as the Random Forest — the extra 7 features mainly earn
their keep at *lower* amplitude ratios, where the anomaly is closer to
the noise floor and a single statistic stops being enough (see
[`identifying_anomalies/MODEL_ARCHITECTURE.md`](identifying_anomalies/MODEL_ARCHITECTURE.md#making-this-harder--more-realistic)
for how to bring that regime back). See `plots/confusion_matrices.png` and
`plots/roc_comparison_rf_vs_baseline.png`.

Reconstructed-window quality on the held-out anomaly files:

- **mean IoU ≈ 0.97** against the true window
- **average start/end boundary error ≈ 0.25s**
- all three anomaly-free control files correctly produced no predicted
  window in this run (`eval_per_file.csv`, `iou = 1.0`)

Most informative features by Random Forest importance: `inst_freq_std`,
`lsq_residual_energy`, `rms` (see `plots/feature_importances.png`); see
`plots/amplitude_ratio_sweep.png` for how F1/IoU vary across the
amplitude-ratio sweep.
